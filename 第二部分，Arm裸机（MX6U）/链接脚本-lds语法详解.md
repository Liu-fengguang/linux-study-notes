# 链接脚本 .lds 语法详解

> 链接脚本告诉链接器：每块代码放在内存的哪个绝对地址上。

---

## 完整脚本

```lds
SECTIONS {
    . = 0x87800000;

    .text : {
        start.o
        *(.text)
    }

    .rodata ALIGN(4) : { *(.rodata*) }
    .data ALIGN(4) : { *(.data) }

    __bss_start = .;
    .bss ALIGN(4) : { *(.bss) *(COMMON) }
    __bss_end = .;
}
```

---

## 逐行拆解

### `SECTIONS { ... }`

段定义总入口。里面规定代码段、数据段、bss 段各放哪里。

### `. = 0x87800000`

| 符号 | 含义 |
|------|------|
| `.` | 定位计数器，当前内存地址指针 |
| `= 0x87800000` | 把起始地址钉在 DDR 基地址上 |

之后所有代码从这个地址往后排。为什么是 `0x87800000`：i.MX6ULL 外接 DDR 的范围 `0x80000000~0x9FFFFFFF`，选这个地址作为裸机程序的固定入口。

### `.text : { ... }` — 代码段

```lds
.text : {
    start.o
    *(.text)
}
```

| 行 | 含义 |
|----|------|
| `start.o` | 把启动文件放在最前面（CPU 上电第一条指令从这开始） |
| `*(.text)` | 其余所有 `.o` 的代码段接在后面 |

**为什么 start.o 必须排第一**：CPU 从 `0x87800000` 开始执行，第一行必须是 `_start`（设栈、设 SVC 模式），然后才跳 C。如果某个 C 函数排在第一，栈还没设，CPU 直接跑飞。

> 弹幕：`.text` 是一个输出段，存放程序代码，`*` 是通配符，把所有文件的 `.text` 合并到这里。

### `.rodata ALIGN(4)` — 只读数据

```lds
.rodata ALIGN(4) : { *(.rodata*) }
```

| 存什么 | 例子 |
|--------|------|
| `const` 常量 | `const int n = 5;` |
| 字符串字面量 | `printf("hello")` 里的 `"hello"` |

**为什么 ALIGN(4)**：ARM 是 32 位处理器，每次取指令/数据最好从 4 字节整数倍地址开始。不对齐可能导致总线错误或效率暴跌。

> 弹幕：`*(.rodata)` 表示将所有文件的只读数据合并到此处，按 4 字节对齐。

### `.data ALIGN(4)` — 已初始化数据

```lds
.data ALIGN(4) : { *(.data) }
```

| 存什么 | 例子 |
|--------|------|
| 已初始化且非零的全局变量 | `int count = 100;` |
| 已初始化且非零的静态变量 | `static int flag = 1;` |

---

### `.bss` + `__bss_start / __bss_end` — 未初始化数据

```lds
__bss_start = .;
.bss ALIGN(4) : { *(.bss) *(COMMON) }
__bss_end = .;
```

| 存什么 | 例子 |
|--------|------|
| 未初始化的全局变量 | `int buffer[1024];` |
| 初始化为 0 的全局变量 | `int flag = 0;` |
| 静态变量（未初始化） | `static int cnt;` |

**.bss 不占 bin 文件空间**

.bss 段里全是 0，存进 bin 纯属浪费。但 C 标准规定未初始化全局变量默认值必须是 0。

`__bss_start` 和 `__bss_end` 打上起止标记，汇编启动代码 `startup.s` 在进入 `main()` 之前，用循环把这块内存全部清零。

```asm
ldr r0, _bss_start
ldr r1, _bss_end
mov r2, #0
bss_loop:
    cmp r0, r1
    beq bss_done
    str r2, [r0]
    add r0, r0, #4
    b bss_loop
bss_done:
```

> 弹幕：`__bss_start` 标记 BSS 段的起始内存位置，`__bss_end` 标记结束位置，汇编里靠这两个标号来清零。

---

## 各段对比

| 段名 | 存什么 | 占 bin 空间 | 需清零 |
|------|--------|------------|--------|
| `.text` | 代码指令 | ✅ | ❌ |
| `.rodata` | const 常量、字符串 | ✅ | ❌ |
| `.data` | 已初始化的全局/静态变量 | ✅ | ❌ |
| `.bss` | 未初始化的全局/静态变量 | ❌ 不占 | ✅ 启动时清 |
