# 汇编符号与内存布局

> .global / #define / typedef 的区别、单双下划线、重定位、段名 vs 边界符号。

---

## 一、.global 是什么？和 #define、typedef 有什么区别？

**完全不同的维度**，不能混为一谈。

| 语法 | 发生在 | 作用 | 分配内存 |
|------|--------|------|----------|
| `#define` | 预处理 | 纯文本替换（把 A 换成 B） | ❌ |
| `typedef` | 编译 | 给类型起别名（`u32` = `unsigned int`） | ❌ |
| `.global` | 汇编+链接 | 把标号对外公开，其他文件能找到 | ❌ 只是一个名册条目 |

### .global 的本质

默认情况下，你在 `start.s` 里写的标号（如 `_start`）只在**当前文件**可见，相当于 C 语言的 `static`。

```asm
.global _start      @ 把 _start 写进对外花名册
_start:             @ 定义标号
    ldr sp, =0x80200000
```

加上 `.global` 后，链接器在拼装所有 `.o` 时就能从其他文件找到这个入口。

## 二、_bss_start 和 __bss_start 有什么区别？

```asm
.global _bss_start       @ 1. 对外公开 _bss_start
_bss_start:              @ 2. 定义一个本地标号
    .word __bss_start    @ 3. 在这个位置留 32 位空间，填入 __bss_start 的值
```

| 符号 | 来源 | 角色 |
|------|------|------|
| `__bss_start`（双下划线） | 链接脚本 `.lds` 定义的变量 | 上帝视角的绝对地址（如 `0x87800FA0`） |
| `_bss_start`（单下划线） | 汇编文件自己起的本地标号 | 一张"小纸条"，存着那个地址 |

### 为什么要绕这一层？

ARM 汇编的 `ldr` 指令只有 32 位，无法直接把一个 32 位地址嵌入指令中。所以要：

1. 链接脚本计算出 BSS 起始地址，存入 `__bss_start`
2. 汇编用 `.word` 开辟 4 字节空间，把 `__bss_start` 的值填进去
3. 给这块空间贴标号 `_bss_start`
4. 代码里 `ldr r0, _bss_start` 读纸条上的值，间接拿到地址

> `_bss_start` 可以叫任何名字（`my_bss_start`、`abc`），叫 `_bss_start` 只是行业惯例。

## 三、为什么 __bss_start 能被替换成真实地址？（重定位）

编译时会经历三个阶段：

### 第一幕：编译阶段（瞎子摸象）

汇编器处理 `start.s` 时，不知道 `__bss_start` 最终在哪个地址（此时所有 `.o` 还没拼到一起）。

汇编器做两件事：
1. 在 `__bss_start` 处**留空**，填假地址 `0x00000000`
2. 在 `.o` 文件末尾附一张**重定位表**："第 12 行需要填入 `__bss_start` 的真实地址，请后续同事补充"

### 第二幕：链接阶段（上帝视角）

链接器 (ld) 拿到所有 `.o` 和 `.lds`：

1. 按链接脚本把 code → data → bss 依次排好
2. 算出 BSS 起点：`0x87800000 + 代码大小 + 数据大小 = 0x87800FA0`
3. 在全局符号表里记下：`__bss_start = 0x87800FA0`

### 第三幕：填字游戏（重定位）

链接器拿出 `.o` 里的重定位表，把当初留空的位置全部替换成真实地址。

> 最终 `.bin` 里 **__bss_start 这个词已经不存在了**，只剩冷冰冰的十六进制地址数字。

验证：`make` 后生成的 `.map` 文件里搜 `__bss_start`，能看到它的最终物理地址。

## 四、这些名字是固定的吗？汇编器天然认识这些符号？

**不是固定的。汇编器不认识 `__bss_start`。**

### 汇编器天然认识的是——段名

| 段名 | 存放内容 | 属性 |
|------|----------|------|
| `.text` | 代码指令 | 只读 |
| `.rodata` | const 常量、字符串 | 只读 |
| `.data` | 已初始化且非零的全局/静态变量 | 读写 |
| `.bss` | 未初始化或初始化为 0 的全局/静态变量 | 读写，不占 bin |
| 堆 Heap | malloc/free 动态内存 | 读写 |
| 栈 Stack | 局部变量、函数参数、返回地址 | 读写，CPU 自动管理 |

汇编器看到 `.text`、`.data`、`.bss` 这些段名，会自动把代码分门别类。

### 边界符号是人类手动定义的

`__bss_start` 是**链接脚本编写者**在 `.lds` 里自己起的变量名：

```lds
__bss_start = .;    @ 把当前地址记下来，起名 __bss_start
.bss : { *(.bss) }
__bss_end = .;      @ BSS 结束，记下终点
```

可以改成任何名字：

```lds
my_dog_start = .;
.bss : { *(.bss) }
my_dog_end = .;
```

只要汇编里同步改 `ldr r0, my_dog_start` 就行。

### 其他常见边界符号

| 符号 | 含义 |
|------|------|
| `_start` | 程序入口 |
| `__text_start` | 代码段起始 |
| `__data_start / __data_end` | 数据段起止 |
| `__bss_start / __bss_end` | BSS 段起止 |
| `__heap_start / __heap_end` | 堆起止 |
| `_end` | 整个程序结束地址（堆从这开始长） |

### 总结

| | 谁认识 | 例子 |
|------|--------|------|
| 段名 | 编译器/汇编器天然认识 | `.text` `.data` `.bss` |
| 边界符号 | 链接脚本定义，汇编通过 `.word` 引用 | `__bss_start` `_end` |

> 段名是房子的功能（厨房/卧室），边界符号是门牌号（由链接器分配具体地址）。
