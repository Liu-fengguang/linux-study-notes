# 工具链详解：objcopy/objdump、文件后缀、自动变量

---

## 一、OBJCOPY 和 OBJDUMP

都是 GNU Binutils 工具集的一员，专门处理编译后的目标文件。

### OBJCOPY（Object Copy）

| 项目 | 说明 |
|------|------|
| 全称 | Object Copy（目标文件复制） |
| 作用 | 格式转换器：`.elf` → `.bin` |
| 比喻 | 豪华精装书 → 纯文字便利贴 |

```makefile
$(OBJCOPY) -O binary -S $(NAME).elf $@
```

| 选项 | 含义 |
|------|------|
| `-O binary` | 输出格式为纯二进制 |
| `-S` | 去掉调试符号和信息 |

> `.elf` 有符号表、调试信息、段表。`.bin` 把这些全扒光，只留机器码。开发板只认纯二进制。

### OBJDUMP（Object Dump）

| 项目 | 说明 |
|------|------|
| 全称 | Object Dump（目标文件转储） |
| 作用 | 反汇编查看器：机器码 → 汇编代码 |
| 比喻 | CD 音乐 → 五线谱 |

```makefile
$(OBJDUMP) -D -m arm $(NAME).elf > $(NAME).dis
```

| 选项 | 含义 |
|------|------|
| `-D` | 反汇编所有段 |
| `-m arm` | 目标架构为 ARM |

> 程序崩溃时，拿错误地址去 `.dis` 里对，精确定位是哪一行代码。

## 二、编译全流程：文件后缀

```
.c/.S ──①编译──→ .o ──②链接──→ .elf ──③转换──→ .bin
                                        └─④反汇编──→ .dis
```

| 后缀 | 全称 | 类型 | 人可读 | 能运行 | 作用 |
|------|------|------|--------|--------|------|
| `.c` | C Source | 文本 | ✅ | ❌ | C 语言源代码 |
| `.S` | Assembly Source（需预处理） | 文本 | ✅ | ❌ | 汇编源码，大写可含 `#include`/`#define` |
| `.o` | Object | 二进制 | ❌ | ❌ | 编译后中间文件，地址未定，不能独立运行 |
| `.elf` | Executable & Linkable Format | 二进制 | ❌ | ✅（需调试器） | 链接后完整程序，有符号表/调试信息 |
| `.bin` | Binary | 二进制 | ❌ | ✅（直接烧录） | 纯机器码，喂给开发板 |
| `.dis` | Disassembly | 文本 | ✅ | ❌ | 反汇编文件，调试查错用 |

### `.S`（大写）vs `.s`（小写）

| | `.S`（大写） | `.s`（小写） |
|------|------------|------------|
| 预处理 | 需要（支持 `#include` `#define`） | 不需要，纯汇编 |
| 编译器处理 | 先 cpp 预处理 → 再汇编 | 直接汇编 |

### `.o` — 中间产物

每个 `.c`/`.S` 生成一个对应 `.o`。里面有机器码 + 符号表（函数名/变量名），但**不知道彼此的地址**。例如 `main.o` 里调用了 `led_init()`，但还不知道 `led_init` 在内存的哪个位置——等链接器来填。

### `.elf` — 带说明书的完整程序

链接器把所有 `.o` 拼接，给每个函数/变量分配绝对地址。ELF 里除了机器码还有符号表、调试信息、段信息。Linux 系统能直接运行 `.elf`，裸机不行。

### `.bin` — 纯粹口粮

`objcopy` 把 ELF 的"说明书"全撕掉，只留机器码。i.MX6ULL Boot ROM 看不懂 ELF，只认 bin。

### `.dis` — 查错照妖镜

程序崩了抛出一个地址（如 `0x87800234`），去 `.dis` 搜这个地址，看到对应的汇编指令，就知道是哪行 C 代码炸了。

## 三、:= 赋值与 OBJS 变量

### `:=` vs `=`

| 符号 | 名称 | 行为 |
|------|------|------|
| `=` | 递归赋值 | 用到时才展开，每次重新求值 |
| `:=` | 立即赋值 | 定义时就确定，之后不变 |
| `?=` | 条件赋值 | 变量未定义才赋值 |
| `+=` | 追加 | 往已有值后面加 |

```makefile
CC  := $(CROSS_COMPILE)gcc      # 立即算出 arm-linux-gnueabihf-gcc
OBJS := start.o main.o           # OBJS = "start.o main.o"
```

### OBJS 里为什么有两个值

`start.o` 和 `main.o` 不是两个变量，是**一个变量存了两个值**（空格分隔）：

```makefile
OBJS := start.o main.o

# 用的时候
$(NAME).bin : $(OBJS)        # 展开为 lcdc.bin : start.o main.o
$(LD) ... $^                 # 展开为 start.o main.o
```

## 四、$@ $< $^ 自动变量

| 符号 | 含义 | 记忆 |
|------|------|------|
| `$@` | 目标文件 | @ = 靶心，要命中的目标 |
| `$<` | 第一个依赖 | < = 指向第一个 |
| `$^` | 所有依赖（空格分隔） | ^ = 向上的全部 |

### 在 Makefile 中的展开

```makefile
$(NAME).bin : $(OBJS)
    $(LD) ... $^              # $^ = start.o main.o
    $(OBJCOPY) ... $@         # $@ = lcdc.bin

%.o : %.c
    $(CC) ... -o $@ $<        # 编译 main.c 时 $@=main.o $<=main.c
```

### 速记口诀

```
$@ 目标就是我
$< 第一依赖者
$^ 全部依赖哥
```
