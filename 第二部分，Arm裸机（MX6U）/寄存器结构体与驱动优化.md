# 寄存器结构体与驱动优化

> 告别散落的 `#define`，用结构体把外设寄存器组织起来。

---

## 一、STM32 寄存器结构体思路

STM32 的做法：把一个外设的所有寄存器用一个结构体封装，再让结构体指针指向外设基地址。

```c
// STM32 风格：GPIO 外设 = 一个结构体
typedef struct {
    volatile unsigned int MODER;    // 模式寄存器
    volatile unsigned int OTYPER;   // 输出类型
    volatile unsigned int OSPEEDR;  // 速度
    volatile unsigned int PUPDR;    // 上下拉
    volatile unsigned int IDR;      // 输入数据
    volatile unsigned int ODR;      // 输出数据
    volatile unsigned int BSRR;     // 位操作
} GPIO_TypeDef;

// 外设基地址 → 结构体指针
#define GPIOA  ((GPIO_TypeDef *)0x48000000)
// 使用
GPIOA->ODR |= (1 << 3);
```

**为什么这么做**：
- 所有寄存器归在一个名下，不散落
- 编译器自动计算每个成员的偏移地址
- 写代码和读数据手册的寄存器表一一对应

## 二、移植到 i.MX6ULL

原始写法（散落 `#define`）：

```c
#define GPIO1_DR   (*(volatile unsigned int *)0x0209C000)
#define GPIO1_GDIR (*(volatile unsigned int *)0x0209C004)
```

结构体写法：

```c
// 1. 定义 GPIO 寄存器结构体
typedef struct {
    volatile unsigned int DR;       // 0x00 数据寄存器
    volatile unsigned int GDIR;     // 0x04 方向寄存器
    volatile unsigned int PSR;      // 0x08 状态寄存器
    volatile unsigned int ICR1;     // 0x0C 中断控制 1
    volatile unsigned int ICR2;     // 0x10 中断控制 2
    volatile unsigned int IMR;      // 0x14 中断屏蔽
    volatile unsigned int ISR;      // 0x18 中断状态
    volatile unsigned int EDGE_SEL; // 0x1C 边沿选择
} GPIO_Type;

// 2. 外设基地址 → 结构体指针
#define GPIO1 ((GPIO_Type *)0x0209C000)

// 3. 使用（和 STM32 一模一样）
GPIO1->GDIR |= (1 << 3);       // 设输出
GPIO1->DR   &= ~(1 << 3);      // 输出低电平
```

## 三、地址连续性规则（重要）

结构体成员按声明顺序**连续排列**，编译器自动算偏移。但如果寄存之间有空洞，必须手动占位。

```c
// ❌ 错误：假设 ICR1(0x0C) 和 ISR(0x18) 之间有 0x10 没定义
typedef struct {
    volatile unsigned int ICR1;     // 0x0C
    // 缺少占位 → ISR 会被放在 0x10，而不是 0x18
    volatile unsigned int ISR;      // 本应是 0x18
} GPIO_Type;

// ✅ 正确：用保留字段占位
typedef struct {
    volatile unsigned int ICR1;     // 0x0C
    volatile unsigned int ICR2;     // 0x10
    volatile unsigned int RESERVED; // 0x14 占位
    volatile unsigned int ISR;      // 0x18
} GPIO_Type;
```

> 对应数据手册寄存器表，逐行看地址，不漏不跳。

## 四、修改驱动三步骤

### ① 添加清除 BSS 段代码

在 `startup.s` 中加入 BSS 清零循环（前面笔记已详解），保证结构体中未初始化的全局变量为 0。

### ② 添加寄存器结构体

把散落的 `#define` 宏替换为结构体定义。所有外设照此模式：

| 外设 | 基地址 | 结构体名 |
|------|--------|----------|
| GPIO1 | `0x0209C000` | `GPIO_Type` |
| CCM | `0x020C4000` | `CCM_Type` |
| IOMUXC | `0x020E0000` | `IOMUXC_Type` |

### ③ 修改驱动使用结构体

```c
// 原始
#define CCM_CCGR1 (*(volatile unsigned int *)0x020C406C)
CCM_CCGR1 |= (3 << 26);

// 结构体
#define CCM ((CCM_Type *)0x020C4000)
CCM->CCGR1 |= (3 << 26);
```

## 五、对比

| | 散落 #define | 结构体 |
|------|-------------|--------|
| 可读性 | 差，每行一个地址 | 好，按外设归类 |
| 维护 | 改地址找半天 | 只改基地址 |
| 新增寄存器 | 加一行 #define | 在结构体对应位置加成员 |
| 编译检查 | 无，写错地址不报 | 成员名写错编译器直接报 |
| 数据手册对应 | 要靠注释 | 结构体成员 = 寄存器表 |
