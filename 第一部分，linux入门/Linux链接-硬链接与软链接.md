# Linux 链接：硬链接与软链接

## 概念对比

| | 硬链接 (hard link) | 软链接 (symbolic link) |
|------|------|------|
| 本质 | 指向同一个 inode | 指向文件路径（快捷方式） |
| 跨文件系统 | 不可以 | 可以 |
| 链接目录 | 不可以 | 可以 |
| 删除原文件后 | 链接仍可用 | 链接失效（断链） |
| inode | 相同 | 不同 |
| 创建方式 | `ln a.txt b.txt` | `ln -s a.txt b.txt` |
| 识别 | `ls -l` 第 2 列（硬链接数） | `ls -l` 显示 `->` 指向路径 |

## 指令

| 命令 | 作用 |
|------|------|
| `ln file1 hardlink` | 创建硬链接 |
| `ln -s file1 softlink` | 创建软链接 |
| `ln -s /absolute/path/file1 link` | 软链接用绝对路径 |
| `ls -li` | 查看 inode 号，确认是否为硬链接 |
| `readlink softlink` | 查看软链接指向的真实路径 |
| `unlink link` | 删除链接 |

## 使用建议

| 场景 | 用 | 原因 |
|------|------|------|
| 多个入口指向同一文件 | 硬链接 | 删除一个不影响另一个 |
| 链接目录 | 软链接 | 硬链接不支持目录 |
| 跨分区链接 | 软链接 | 硬链接不能跨文件系统 |
| 简化路径（如 `/opt/nginx-1.25` → `current`） | 软链接 | 版本切换方便 |
| 备份重要文件防误删 | 硬链接 | 只有所有硬链接删除才释放数据 |

> **软链接必须用绝对路径**。相对路径的软链接依赖当前工作目录，移动链接文件后就会断链。例如 `ln -s /home/alice/data.txt link` 而非 `ln -s ../data.txt link`。
