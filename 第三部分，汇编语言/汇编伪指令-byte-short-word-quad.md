# 汇编伪指令：.byte .short .word .quad

> `.word` 永远 32 位，和 CPU 位数无关。ARM 架构的硬性规定。

---

## 一、为什么没有 .bit？

CPU 寻址最小单位是**字节**（8 bit）。内存地址按字节编号，无法单独为一个 bit 分配地址。

改某个 bit：把整字节读出来 → `|=` 或 `&=~` 修改 → 整体写回。

---

## 二、GNU 汇编器容量语法

| 伪指令 | 等价写法 | 大小 | 对应 C 类型 |
|--------|----------|------|------------|
| `.byte` | | 8 位（1 字节） | `char` |
| `.short` | `.half` | 16 位（2 字节） | `short` |
| `.word` | `.int` `.long` | **32 位（4 字节）** | `int` / `long` |
| `.quad` | `.xword` (ARM64) | 64 位（8 字节） | `long long` |

> `.word` `.int` `.long` 在 32 位系统上完全等价，都开辟 32 位空间。

---

## 三、ARM 架构的绝对定义

| 术语 | 位数 | 永不变 |
|------|------|--------|
| Half-word（半字） | 16 位 | ✅ |
| Word（字） | **32 位** | ✅ |
| Double-word（双字） | 64 位 | ✅ |

> ARM 为保持向下兼容，在 32 位 ARMv7 和 64 位 ARMv8/v9 上，`.word` 永远 = 32 位。

---

## 四、32 位 vs 64 位 ARM 对照

| | ARMv7 (32bit) | ARMv8/v9 (64bit AArch64) |
|------|--------------|--------------------------|
| 寄存器宽度 | 32 位 | 64 位 |
| `.word` 大小 | 32 位 | **还是 32 位** |
| 存 64 位地址用什么 | 不存在这个问题 | `.quad` 或 `.xword` |

```asm
@ 错误 — 在 ARM64 下用 .word 存 64 位地址，会被截断
.word 0xFFFF000012345678   @ 只保留低 32 位，高 32 位丢失

@ 正确 — 用 .quad 或 .xword
.quad 0xFFFF000012345678
```

---

## 五、示例：不同大小分配

```asm
flag:       .byte   0x01        @ 1 字节
count:      .short  0x1234      @ 2 字节
address:    .word   0x87800000  @ 4 字节（32 位地址）
bigaddr:    .quad   0x4000000000 @ 8 字节（64 位地址）

bss_start:  .word   __bss_start  @ 链接脚本给的 32 位地址填入 4 字节空间
```

## 六、速记

| 想存的东西 | 用什么 |
|-----------|--------|
| 一个字节 | `.byte` |
| 16 位短整数 | `.short` |
| 32 位地址/32 位整数 | `.word` / `.int` |
| 64 位地址/64 位整数 | `.quad` |
| Flash/外设寄存器地址 | `.word`（32 位 ARM）|
